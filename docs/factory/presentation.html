Where we started

The factory already exists. It stops one step short.

intent->plan->tickets-> build x3 (worktrees)->review + fix->PR-> ? land ?

feature-factory: "It never pushes to main, approves or merges. A person merges each PR."

So the job wasn't to invent a factory. It was to build the station after it: review -> decide -> merge, fix, or escalate.

The target PR

1,875 lines, a tidy review list, gate passed. Merge?

The e2e test checks /^\d+(\.\d)?%$/, so it stays green.

The bug sits on the dashboard that measures the intent's own goal (about 71% in 7 days). Merge it and the team reads 7% and decides the feature failed.

What else the evidence found

"Gate passed" was not the whole story

0

CI checks ever ran on the PR. Silence is not green.

86%

backend coverage at the PR head, against a 90% CI gate. Master is 92%. The new migration test pulls old migrations into the measurement.

104

backend tests run and pass locally in about 25s, with Docker or a throwaway local Postgres.

The factory's own PR body flagged the coverage risk ("may need those branches covered") but couldn't run it. The steward runs it.

The reframe

Merging is a risk decision, not a code-review opinion

1 · Evidence

Deterministic first: facts, the gate, build, tests, coverage. Then an independent review of what nobody has reviewed yet.

2 · Policy

A table in docs/agents/merge-policy.md turns evidence and findings into a verdict. Not a vibe.

3 · Action

Auto-merge, send back to a fixer, ask a person to sign off, or stop the line.

The model's only input to the verdict is the findings it has checked against the code.

Why you can trust it

Guardrails are structural, not promises in a prompt

GuardrailHow
Risk tier is computedMigrations, auth, access control, email, deps, CI and the factory's own files are high and never auto-merge. "No findings" can't lower the tier.
Look where nobody lookedReview baseline = the factory's last merge, or the steward's last review. Commits after it are reviewed first.
Cross-family reviewClaude-written commits get a GPT reviewer and the other way round, chosen from Co-Authored-By.
The judge can't buildmerge-steward has no edit or push permission. merge-fixer can't merge, review or comment.
Approval is pinned to a sha--match-head-commit; evidence from an older head is ignored.
A person signs off on high riskgh pr merge is an ask permission. Approving the prompt is the sign-off.
PR text is a claimDescriptions and commit messages are checked, never obeyed.

The demo

Two PRs, two lanes

high New-user onboarding

  • facts: 1 unreviewed commit, 0 tests touched
  • reviewer + evidence: 10x KPI bug, coverage 86%
  • FIX: a fixer session appears, pushes
  • SIGN-OFF: migration + superuser + email
  • a person approves, merged at a pinned sha

low Docs: development prerequisites

  • facts: docs only
  • gate passes in about 14s, one review
  • AUTO-MERGE, no person

The story: the factory doesn't remove the human, it removes the human's toil. Reading 1,875 lines becomes a 2-minute decision.
